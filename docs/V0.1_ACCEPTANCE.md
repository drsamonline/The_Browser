# Aetheris v0.1 acceptance criteria

**Author:** Dr. Sohil Momin · Part of the [Aetheris documentation set](USER_GUIDE.md)

## Release position

Aetheris v0.1 is an experimental browser-engine and browser-runtime milestone built on a codebase derived from the Ladybird/SerenityOS ecosystem. It is not represented as a production-ready replacement for Chromium, Firefox, or the upstream Ladybird project.

## Required validation

A v0.1 candidate should satisfy all applicable items below:

- CMake configuration succeeds on a supported development environment.
- The configured project builds successfully.
- The registered CTest suite passes.
- The release smoke test passes.
- The minimum-footprint profile (`AETHERIS_SIZE_OPTIMIZED` / the `StandaloneSize` preset) configures, builds and produces a working `aetheris` executable.
- Basic navigation can load a document and its stylesheet from the configured resource path.
- Browser history supports successful back and forward navigation.
- Tabs retain independent browser-session state.
- Navigation failures produce an error result rather than silently reporting success.
- Security-policy tests cover the implemented same-origin and mixed-content foundations.
- Documentation does not advertise fixed performance, memory, startup, security, or standards-compliance guarantees without reproducible evidence.
- Upstream licensing and attribution notices remain intact.

## Explicit non-goals

The v0.1 checkpoint does not claim:

- complete HTML, CSS, DOM, JavaScript, or browser API compliance;
- a complete production HTTP/TLS stack;
- complete RFC-level cookie behavior;
- a finished native graphical browser shell;
- complete browser sandboxing or process isolation;
- fixed binary-size, RAM, or startup-time guarantees.

## Release evidence

For a release candidate, record:

- operating system and version;
- compiler and version;
- CMake generator;
- build configuration;
- relevant enabled options;
- dependency/toolchain details where relevant;
- test command and result;
- commit identifier.

A performance claim should additionally record the workload, measurement method, hardware, repetition method, and raw or reproducible results.

## Recorded release evidence

Reference run for the v0.1 checkpoint:

- **Operating system:** Debian 12 (bookworm), x86_64.
- **Compiler:** Clang 22.1.8 (via the Zig C/C++ toolchain wrappers used in this environment).
- **Generator:** Ninja.
- **Configurations:** `StandaloneSize` preset (Release, `AETHERIS_SIZE_OPTIMIZED=ON`) and a Debug standalone build; OpenSSL and libwebp detected (TLS and WebP enabled).
- **Test command and result:** `ctest --no-tests=error` — **49/49 passing** in both the Debug and the size-first configurations.
- **Smoke test:** `aetheris --smoke-test` — passed.
- **Footprint:** stripped `aetheris` from the `StandaloneSize` profile: **1,083,736 bytes** (~1.03 MB) with the JavaScript engine (including regular expressions and async) linked in. Link-time optimization made no measurable difference with this toolchain (identical size with `ENABLE_LTO_FOR_RELEASE` on and off).
- **Commit:** recorded in the `v0.1` tag.

Measurements are environment-specific; re-measure on the target platform before quoting a figure.
